# 06. 머신러닝 모델링 진행 상황 및 디버깅 기록

## 1. 초기 구현 및 목표

- **목표**: Firth 회귀분석에서 도출된 유의미한 변수들을 사용하여, 세 그룹(total, EOCRC, LOCRC)에 대한 생존 예측 머신러닝 모델(Random Forest, GBM, XGBoost)을 구축하고 평가한다.
- **데이터**: `data/modeling_datasets/` 폴더에 미리 분할된 훈련/검증 데이터를 사용한다.
- **주요 기술**: `caret` 패키지를 활용한 모델 훈련, 10-fold 교차 검증, `themis` 패키지의 SMOTE를 이용한 클래스 불균형 처리.

---

## 2. 디버깅 과정 및 오류 해결

### 문제 1: `predict on NULL` 오류

- **현상**: `preProcess` 함수로 결측치 대치 모델을 생성한 후, `predict` 함수를 적용하는 과정에서 `NULL` 객체에 대한 `predict`를 시도한다는 오류가 발생했다.
- **가설 1**: 데이터에 결측치가 없어 `preProcess`가 `NULL`을 반환한다.
- **검증 1**: 데이터 로딩 시 `na.strings = ""` 옵션을 추가하여 빈 문자열을 `NA`로 명시적으로 변환했으나, 오류가 지속됨.
- **가설 2**: 문제의 원인은 다른 곳에 있다. `preProcess` 직전 데이터의 `NA` 상태를 직접 확인한다.
- **검증 2**: 진단 코드를 추가하여 `NA` 개수를 확인한 결과, 예측 변수에는 `NA`가 없었지만, **결과 변수인 `사망여부` 열의 모든 값이 `NA`로 변환되어 있었음**을 발견했다.

### 문제 2: `missing values in object` 오류

- **현상**: `사망여부`의 `NA` 문제를 해결하기 위해 수동으로 결측치 대치 로직을 재구성하자, `caret::train` 함수 내부에서 결측치 오류가 다시 발생했다.
- **원인 분석**: `사망여부`의 `NA`를 제거해도, 예측 변수 자체에 숨겨진 결측치가 여전히 남아있었다. 수동으로 데이터를 처리하는 방식이 `caret`의 내부 검증 메커니즘과 충돌을 일으켰다.
- **해결 시도**: `caret::train` 함수의 내장 기능을 활용하기로 결정. `na.action = na.pass`와 `preProcess = c('bagImpute')` 인자를 `train` 함수에 직접 전달하여, `caret`이 내부적으로, 그리고 가장 안정적인 시점에 결측치를 처리하도록 변경했다.

### 문제 3: `One or more factor levels... has no data` 오류

- **현상**: 결측치 오류를 해결하자, 교차 검증 시 특정 fold에 데이터가 없다는 새로운 오류가 발생했다.
- **가설**: 클래스 불균형이 극심하여, 특정 fold에 "Alive" 또는 "Dead" 클래스가 하나도 포함되지 않는다.
- **검증**: 훈련 직전, `사망여부`의 클래스 분포를 확인하는 진단 코드를 추가했다.
- **최종 원인 발견**: 진단 결과, `total` 그룹의 훈련 데이터에 **"Alive" 0개, "Dead" 0개**로 나타났다. 이는 `사망여부` 열의 원본 값이 `0` 또는 `1`이 아니었기 때문에, `factor(..., levels=c(0,1))` 변환 시 모든 값이 `NA`가 되었고, 이어진 `filter(!is.na(사망여부))` 단계에서 **모든 데이터 행이 제거**되었기 때문이었다.

## 3. 현재 상태 및 다음 단계

- **현재 상태**: 모든 오류의 근본 원인이 **`사망여부` 열의 원본 데이터 형식과 `factor` 변환의 불일치**로 명확하게 규명되었다.
- **다음 단계**: 
    1. `사망여부` 열의 실제 데이터 값을 확인한다. (예: "생존"/"사망", "0"/"1" 등)
    2. 확인된 실제 값에 맞게 `factor` 함수의 `levels`와 `labels`를 올바르게 수정한다.
    3. 이 근본적인 문제를 해결한 후, 최종적으로 스크립트를 실행하여 모델링을 완료한다.

## 1. 초기 모델링 스크립트 개발

- **목표**: Firth 회귀분석에서 도출된 유의미한 변수들을 사용하여 GBM, XGBoost, Random Forest 모델을 훈련하고, 각 모델의 예측 성능을 AUC 값으로 평가한다.
- **구현**: `scripts/06_ml_modeling.R` 스크립트를 작성했다.
  - Firth 회귀분석 결과(`p < 0.05`, 신뢰구간이 1을 포함하지 않음)를 바탕으로 각 그룹(total, eocrc, locrc)의 모델링에 사용할 변수를 동적으로 선택하는 기능을 구현했다.
  - `caret` 패키지를 활용하여 10-fold 교차검증 및 SMOTE를 적용한 모델 훈련 파이프라인을 구축했다.
  - 초기 스크립트는 단일 전처리 데이터를 불러와 내부적으로 훈련/테스트 데이터로 분할하도록 설계되었다.

## 2. 발생한 문제 및 해결 과정

머신러닝 모델링 스크립트 실행 과정에서 여러 단계의 오류가 발생했으며, 이를 해결하기 위한 디버깅 과정을 아래에 기록한다.

### 문제 1: 잘못된 데이터 로딩 방식
- **오류**: 스크립트가 단일 데이터셋(`preprocessed_data.rds`)을 불러오도록 설계되었으나, 실제로는 `data/modeling_datasets/` 폴더에 그룹별(`total`, `eocrc`, `locrc`) 및 용도별(`_train.csv`, `_valid.csv`)로 데이터가 이미 분할되어 있었다.
- **해결**: `train_and_evaluate_models` 함수를 수정하여, 각 그룹에 맞는 `_train.csv`와 `_valid.csv` 파일을 직접 불러오도록 데이터 로딩 로직을 전면 재작성했다.

### 문제 2: CSV 파일의 열 이름 불일치
- **오류**: `get_significant_vars` 함수 실행 중 `p.value` 열을 찾을 수 없다는 오류가 발생했다.
- **원인**: Firth 회귀분석 결과 CSV 파일의 실제 열 이름이 `p_value`, `upper_ci`, `lower_ci`, `variable` 등 스크립트에서 예상한 `p.value`, `upper.95`, `lower.95`, `Variable`과 달랐다.
- **해결**: `get_significant_vars` 함수 내에서 사용하는 모든 열 이름을 실제 CSV 파일의 헤더와 일치하도록 수정했다.

### 문제 3: 종속 변수 이름 불일치
- **오류**: 모델 훈련 데이터에서 `status` 열을 찾을 수 없다는 오류가 발생했다.
- **원인**: 모델링에 사용하는 `_train.csv` 파일의 종속 변수(결과 변수) 열 이름이 `status`가 아닌 `사망여부`였다.
- **해결**: 스크립트 전체에서 종속 변수를 지칭하는 변수 `target`의 값을 `"사망여부"`로 변경했다.

### 문제 4: 결측치(NA)로 인한 모델 훈련 실패
- **오류**: `missing values in object` 또는 `Every row has at least one missing value` 오류가 반복적으로 발생하며 모델 훈련이 중단되었다.
- **원인 분석**:
  1.  **초기 원인**: 모델 훈련에 사용된 특징(feature) 열에 결측치가 포함되어 있었다. `randomForest`와 같은 모델은 결측치를 자동으로 처리하지 못한다.
  2.  **`na.omit` 실패**: 결측치가 있는 행을 모두 제거하는 `na.omit` 방식을 적용했으나, 이로 인해 학습 데이터가 모두 제거되어 훈련을 시작할 수 없는 문제가 발생했다. 이는 선택된 특징들의 조합에 결측치가 광범위하게 분포해 있음을 시사한다.
  3.  **특징 이름 불일치**: 회귀분석 결과에서 추출한 특징 이름(예: `MSI_STATUSstable`)은 원-핫 인코딩된 형태지만, 실제 학습 데이터에는 원본 범주형 변수(예: `MSI_STATUS`)가 포함되어 있어 데이터 선택 단계에서부터 문제가 발생하고 있었다.

- **진행 중인 해결 방안**: 현재 `caret`의 `preProcess = 'bagImpute'` 옵션을 사용하여 결측치가 있는 행을 삭제하는 대신, 모델 기반 대치(imputation)를 통해 결측치를 채우는 방식으로 접근하고 있다. 이 과정에서 `preProcess` 인수의 위치를 `trainControl`이 아닌 `train` 함수로 옮기는 등 여러 차례 수정을 진행했다.
